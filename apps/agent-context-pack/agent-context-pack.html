What's Inside

One file: agent-context-pack.md. Markdown your agent can read, with a YAML front-matter block at the top for tools that parse structured data. Both say the same thing, so the pack works whether your agent reads plain text or structured fields.

The file contains

  • YAML front-matter — pack name, version, last-updated date, owner timezone and language, and load rules for the agent.
  • Section 1 — Identity: name, what to call you, pronouns, timezone, language, general location, contact email.
  • Section 2 — Facts: employment, work history, education, licence, lifting limit, available hours, transport, internet, devices — facts the agent uses directly instead of re-asking.
  • Section 3 — Preferences: communication style, job-search defaults, resume rules, spending rules, message rules, working style.
  • Section 4 — Hard limits: eight non-negotiable rules, including no SSN/passwords/signatures, no final submit clicks, no scored assessments, no impersonation, no voice clone, no invented facts, no money moves, and no sharing the file.
  • Section 5 — Standing rules: recurring-task rules — verify postings are live, check both inboxes, never re-propose rejected items, verify before stating a fact.
  • Section 6 — Open items: a table of things still waiting, with status and date.
  • Section 7 — Changelog: dated record of every change, newest first — never delete entries.
  • Section 8 — Template checklist: tick-boxes to complete before first use.
  • How-to-use note at the top of the file: save a copy, replace the example values, load it into your agent, update the changelog.
Example data only: the pack ships filled with clearly-marked fictional example data (a made-up person, "Alex Example") so you can see how every section works. Replace every value with your own facts before loading it into an agent. Nothing in the file is a real person's data.

How To Use It

1. Save a copy

Save the file as my-context-pack.md. Replace every example value with your own facts. Delete any section that does not apply to you.

2. Load it into your agent

Paste it into your agent's context, attach it, or point the agent at the file — whichever your agent supports. Load it at the start of every session, before asking the agent anything.

3. Stop re-answering

If a fact is in the pack, the agent uses it directly. If a fact is missing, answer once, then add it to the pack so it is never asked again.

4. Keep the changelog current

Every time a fact changes, add a dated row to Section 7 with what changed. Keep old entries — the history is how you and your agent stay in sync.

5. Keep it private

This file holds personal facts. Store it where only you and your agent can read it. Never send it to a third party, tool, or service without deciding to do so yourself.

What the pack does NOT do: it does not give your agent new powers, it does not sign or submit anything for you, and it does not speak as you. Your SSN, passwords, security answers, signatures, scored assessments, and final submit clicks stay yours — the pack says so in Section 4, in writing, every session.
